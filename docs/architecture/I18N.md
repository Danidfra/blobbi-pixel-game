# Languages and readable text (M11B)

**Status: IMPLEMENTED** (automated tests: `tests/i18n.test.ts`, `tests/readability.test.ts`). English, Brazilian
Portuguese and Spanish are complete; the architecture takes more languages without code changes beyond a catalogue.
Translations are written by hand (no machine translation, nothing at run time, no server).

## 1. How a language is chosen

| Step | Rule | Code |
|---|---|---|
| First visit | the browser's languages, in order: `pt-*` → `pt-BR`, `es-*` → `es`, `en-*` → `en`, the first match wins; anything else → `en` | `detectLocale` (`src/i18n/index.ts`) |
| A choice | SETTINGS → GAME → LANGUAGE (LEFT/RIGHT or ENTER), or the language button on every title page (or **L** there, except while naming an island) | `nextLocale` (`ui/screens/settings.ts`), `TitleScreen.drawLanguage` |
| Kept | only an explicit choice is stored, per browser, in `blobbi-pixel-lab:locale`; never in a save | `src/playground/main.ts` |
| Live | screens read the catalogue as they draw, the content text is rewritten in place, HUD cards are cached by language: a change shows on the next frame, no restart | `setLocale`, `onLocaleChange` |

The language is **presentation only**: world generation, identities, the simulation's state and saves never read it
(`tests/i18n.test.ts` generates and saves the same island in all three languages and compares terrain, objects and
the saved record byte for byte).

## 2. Two kinds of text

**Interface messages** (`src/i18n/messages/<locale>.ts`, 801 keys): stable semantic keys (`settings.language`,
`prompt.pickUp`, `notice.questDone`...). `en.ts` is the source; `pt-BR.ts` and `es.ts` are typed `Catalog`, so a
missing or extra key is a **type error**, and the tests check the same keys, the same parameters and no empty text.

- `t(key, params)`: `{name}` interpolation; a message may be plural (`{ one, other, ... }`, chosen by
  `Intl.PluralRules` from the `count` parameter); a key missing in a language falls back to English; a key no
  catalogue has returns the key itself and is recorded in `missingKeys` (a test scans the source for every literal key
  and fails if one is unknown).
- `upper()` and `sentence()` use the language's own case rules.
- `tOr(key, fallback)`: keys built at run time from content ids.

**Content text** (`src/content/text.ts`, 874 keys, 6 280 English words): item names, plurals and descriptions,
quests and requests, journal notes, the guide, house levels and styles, the Carrier's observations and hums, harmony
and friendship names, growth stages and biomes, places, tutorial tips. The English stays in the content files (they
remain the source); the overlay remembers each field's English once and, on a language change, writes the
translation over the same objects (`item.<id>.label`, `quest.<id>.title`...). Every screen that reads `itemLabel()`
or `quest.title` is translated without its own changes; back to English restores the originals exactly (tested).
Copies made at load (the objective list, buildings, crops, meals) are registered under the same keys.

Never translated: ids of any kind (items, quests, recipes, buildings, carriers, kinds), save fields, Nostr kinds,
Blobbi identifiers, island names the player chose, the generated island names (`worldName`: proper names, and
deterministic from the identity), the developer lab's sidebar and the dev tools.

**Rule for logic:** nothing may compare display text. `house-art.ts` compares `WALL_MATERIALS[...].name ===
'fieldstone'`, so those source arrays are deliberately *not* registered; the HOME screen shows its own copies
(`STYLE_OPTIONS`).

## 3. Nouns in sentences (gender, articles, contractions)

Messages about a thing receive a family of parameters built by `itemNoun(id)`, `buildingNoun(kind)`, `cropNoun(kind)`
(`src/content/text.ts`): `name`, `names`, `the`, `a`, `of_the`, `in_the`, `on_the`, `to_the`. English builds
"the stone", "a stone"; Portuguese and Spanish use each item's grammatical gender (`GENDER_PT_BR`, `GENDER_ES`, one
entry per item, tested) and contract: "a pedra / da pedra / na pedra / à pedra", "el palo / del palo / al palo". A
translation may pick any member of the family (the parameter test treats them as one).

Counts: plural messages (`{ one, other }`); where English counts in words ("the two trees", the house-expansion
advice) the English-only helper is a parameter named `en_*`, which other languages may leave out.

## 4. Loading

English is built into the main bundle. Each other language is one chunk (`src/i18n/locales/<locale>.ts`: messages +
content + genders, about 32 kB gzip), loaded only when chosen. On start the game waits for the chosen language's
chunk before the first frame (top-level `await` in `main.ts`), so the title never flashes English; if it cannot load
(offline), the game stays in English.

## 5. Text rendering (why accents and readability needed new drawing)

Before M11B every word was drawn in a 3×5 capitals-only bitmap font into a small UI buffer, then magnified by a whole
number (often 1× on phones). It had no lowercase, no accents, and letters such as M/N and Q/9 were hard to tell
apart. Now:

- **`UiSurface`** (`src/ui/surface.ts`): panels, the title and HUD cards keep their layouts in UI pixels, but are drawn
  straight at the screen scale. Boxes, rims and icons look exactly as before.
- **Body font** (`src/ui/fonts/body-font.ts`, `body-large.ts`): a new hand-made readable pixel font in two sizes —
  capitals 7 and 9 pixels, x-height 5 and 6, descenders, proportional widths, accents composed from marks (acute,
  grave, circumflex, tilde, diaeresis, cedilla) plus ¿ ¡ º ª · … — used for sentences, lists, buttons and the HUD.
- **Title font**: the 3×5 capitals stay for panel titles and headings (the game's pixel identity), now with accents
  (marks in the two free rows above a letter, a cedilla below).
- **Choice per scale** (`bodyChoice`): the largest body size whose line (accents to descenders) fits the layouts'
  7-pixel line pitch and whose widest letter fits 4 UI pixels: 1.5×–2.9× → 9 px capitals (7 px at 1.5×), 3× → 14 px,
  4× → 18 px, 5× → 21 px; below 1.5× (a tiny window) the 3×5 capitals as before. Because the body font is never wider
  than the old font, no layout can overflow (and `tests/readability.test.ts` draws every menu in every language at
  phone and desktop sizes and checks that no word leaves its panel and no label its button).
- Text drawn straight on the island scene (the title page's lines) gets a dark shadow.

## 6. Text size (SETTINGS → GAME → TEXT SIZE)

Small / Normal / Large, default Normal, kept with the other settings (`blobbi-pixel-lab:settings`, never in a save;
the pre-M11B "large HUD text" carries over as Large). It replaces MENU SCALE and LARGE HUD TEXT.

| | Menus (largest scale allowed; less on a smaller screen) | Body text in menus | HUD |
|---|---|---|---|
| Small | 2× | one size smaller than the scale allows | 2× |
| Normal | 3× | the largest that fits | 2× |
| Large | 4× | the largest that fits | 3× |

The world camera and its zooms are untouched (tested). Honest limit: menus are fixed layouts, so on a screen where a
3× menu is already the largest that fits (most laptops), Large enlarges the HUD and tips but not the menus; on a big
screen it enlarges both. The panel fit margin went from 8 to 4 pixels, so a 667×375 phone now gets 2× menus
(previously 1×).

## 7. Adding a language

1. `messages/<id>.ts`: a `Catalog` (the compiler lists every missing key).
2. `content/<id>.ts`: the content table and the gender table (`npx tsx scripts/i18n-report.ts --dump file.json`
   writes every content key with its English).
3. `locales/<id>.ts`: the bundle; add the id to `Locale`, `LOCALES`, the loader map and `detectLocale`.
4. Check that both fonts draw every character (`tests/i18n.test.ts` fails otherwise). Scripts beyond Latin (Japanese)
   need glyphs the pixel fonts do not have: a new font, not just a catalogue.

## 8. Known limitations

- Generated island names stay English words (proper names, deterministic from the identity).
- Player-typed island names stay ASCII letters, digits and `. ! -` (an existing test pins that rule; widening it to
  accented letters is a one-line change awaiting the owner's approval).
- The developer lab sidebar, dev tools, diagnostics and console messages stay English.
- The 3×5 title font keeps its old M/N likeness; it is now used only for short headings.
