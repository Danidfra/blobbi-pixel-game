# Blobbi Pixel documentation

This is the entry point for the documentation. The **code is the source of truth**: where a document and the code
disagree, the code wins and the document is the bug ([maintenance rules](#maintenance-rules)).

**Project state (2026-10-12):** M1–M3 are committed on `master`. M4–M7, M8 phase 0 (the playable whale), the M8
intro cinematic and M8 (the beginning and home progression: first-time flow, the intro in play, the first home,
three house levels, customisation, tips, guide, touch, delete safety) and M9 (rest in bed, turtle flipper layering,
earned home styles, four growth stages with the Sanctuary) and M10 phase A (the living ocean: seamless sea,
fishing cast and line, performance work, the up-close camera, marine life), M10 phase B (land clearing and
regrowth, house-expansion advice, the canoe, fishing variety, ocean finds) and M10 phase C (one-island onboarding,
the island's first growth in the story, guaranteed ocean access, clearing at every stage, prepared land, planted
trees saved, side-quest pinning, locked-recipe hints, canoe and sea polish, save safety) are committed on `develop`.
M9 has been played by the project owner, and parts of M10 phase B (the canoe, clearing, house expansion: see the
test plan); M10 phase C has not. Everything since M8 is **IMPLEMENTED — AWAITING MANUAL VALIDATION** unless the test
plan says otherwise: the automated suite passes (see [M10 phase C](milestones/M10C.md)).

## Status labels

| Label | Meaning |
|---|---|
| **IMPLEMENTED** | In the code and covered by automated tests. |
| **PROTOTYPE** | In the code but deliberately partial (for example local-only visiting). |
| **DESIGNED ONLY** | Written down as a design; no code. |
| **PLANNED** | On the roadmap; no design yet. |
| **NOT TESTED** | No person has run the manual test. Automated tests never count as manual approval. |

## Maintenance rules
1. **Code first.** Change the code, then the document in the same change. A document never describes behaviour the
   code lacks unless it is labelled DESIGNED ONLY or PLANNED.
2. **Use the labels** above. Only a person running the manual test may change NOT TESTED to PASS or FAIL, in
   [the test plan](testing/MANUAL-TEST-PLAN.md), with the date and browser.
3. **Do not hand-edit the content catalogue or the player guide**: run `npx tsx scripts/content-catalog.ts` and
   `npx tsx scripts/player-guide.ts` after changing content.
4. **Archived reports are history**: never rewrite them; add a new report or a note in the current documents.
5. **Run `npx tsx scripts/check-docs.ts`** before committing documentation: it checks that relative links and quoted
   `src/`, `tests/` and `scripts/` paths exist.
6. **New systems** get a specification with the 13 sections, test IDs in the plan and a line in this index.
7. **Discrepancies** found between docs and code go to [known issues](testing/KNOWN-ISSUES.md) until fixed.
8. Keep the root README short; detail belongs here.
